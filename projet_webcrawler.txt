=========================================
PLAN DE DÉVELOPPEMENT - PROJET SAAS WEBCRAWLER NO-CODE 
=========================================

Auteur : Thumser Luc
Date de début : 12/11/2025
Technos principales : Django, Scrapy, Celery, Redis, PostgreSQL, Docker
Objectif : Créer un MVP SaaS de webcrawler simple, automatisé, sécurisé, scalable et rentable, avec interface web no-code et résultats téléchargeables.

-----------------------------------------
PHASE 0 - ASPECTS LÉGAUX, ÉTHIQUES ET SÉCURITÉ
-----------------------------------------
Objectif :
Garantir la conformité légale, protéger utilisateurs et développeur, prévenir abus et attaques.

Principes fondamentaux :
- Responsabilité utilisateur : CGU précisent que tout usage illégal ou abusif relève de l’utilisateur.
- Respect RGPD : données minimales (email, mot de passe), fichiers CSV stockés temporairement.
- Limites techniques anti-abus : max 25 URLs par crawl, respect robots.txt, taux de requêtes limité.
- Isolation et sécurité : conteneurs Docker pour chaque worker, logs et monitoring des tâches.
- Transparence : mentions légales, politique de confidentialité, pas de revente de données.

Livrables :
- CGU / Politique de confidentialité / Mentions légales v1
- Processus consentement RGPD
- Page “Utilisation responsable”
- Limites anti-abus implémentées

-----------------------------------------
PHASE 1 - DÉFINITION DU MVP
-----------------------------------------
Objectif :
Définir les fonctionnalités minimales et le public cible.

Tâches :
- Cas d’usage concret (ex: extraction prix e-commerce)
- Fonctionnalités minimales : création compte, ajout URL, lancement crawl, téléchargement CSV
- Liste des données à extraire : titre, prix, stock, lien
- Positionnement : no-code, français, éthique
- Public cible : non-tech (e-commerçants, marketeurs)
- Valeurs : hébergement France, transparence, modèle d’abonnement clair

Livrables :
- Spécification fonctionnelle MVP.txt
- Maquette interface rapide
- Persona principal
- Charte éthique du produit

-----------------------------------------
PHASE 2 - BASE DJANGO
-----------------------------------------
Objectif :
Installer backend solide et API CRUD pour tâches de crawl.

Tâches :
- Création projet Django et app principale
- Configuration base PostgreSQL (SQLite pour début)
- Modèles : User, CrawlTask (status, result_file, created_at)
- API endpoints : POST /task/, GET /task/{id}/
- Interface minimale (template HTML ou API JSON)
- Préparer stockage futur S3/MinIO

Livrables :
- Backend fonctionnel CRUD
- Admin Django opérationnel
- Structure prête pour scalabilité

-----------------------------------------
PHASE 3 - INTÉGRATION SCRAPY + ASYNCHRONE
-----------------------------------------
Objectif :
Intégrer Scrapy, Celery et Redis pour crawl asynchrone et scalable.

Tâches :
- Projet Scrapy séparé
- Spider BasicSpider avec vérif robots.txt avant crawl
- Celery + Redis pour exécution asynchrone
- Django → Celery → Scrapy → CSV
- Logs et monitoring des tâches

Livrables :
- Crawl fonctionnel
- Résultats CSV téléchargeables
- Processus sécurisé et isolé

-----------------------------------------
PHASE 4 - UX / NO-CODE
-----------------------------------------
Objectif :
Rendre l’outil utilisable sans compétence technique.

Tâches :
- Interface drag & drop pour URLs et sélecteurs CSS
- Liste des tâches + statut + bouton téléchargement CSV
- Sélecteurs dynamiques utilisables par le spider
- Feedback utilisateur (progress bar, notifications)
- Prévoir guide rapide / tutoriel intégré

Livrables :
- Interface simple et semi-no-code
- Extraction paramétrable
- UX validée par early testers

-----------------------------------------
PHASE 5 - AUTOMATISATION ET DÉPLOIEMENT
-----------------------------------------
Objectif :
Déploiement fiable et scalable.

Tâches :
- Docker Compose : Django, Scrapy worker, Redis, PostgreSQL
- Déploiement VPS (VPS-2 pour ≤30 utilisateurs, VPS-6 pour >30)
- Monitoring Healthchecks.io / UptimeRobot
- Logs centralisés
- Stockage fichiers : local → S3/MinIO
- Paiement Stripe (optionnel)
- Plan scaling manuel des VPS pour éviter endettement

Livrables :
- Application en ligne
- Crawl automatique
- Monitoring opérationnel et alertes
- Prévision montée en charge sécurisée

-----------------------------------------
PHASE 6 - VALIDATION ET ÉVOLUTION
-----------------------------------------
Objectif :
Tester valeur du produit, retours utilisateurs, identifier améliorations.

Tâches :
- Tests MVP avec early testers
- Collecte feedbacks : bugs, UX, attentes
- Identifier évolutions v2 : interface plus visuelle, multi-sites, planification automatique, export JSON/Google Sheets
- Prévoir gestion des utilisateurs et quotas

Livrables :
- Rapport tests
- Roadmap v2
- Version stable publique

-----------------------------------------
PHASE 7 - GESTION DES COÛTS ET RENTABILITÉ
-----------------------------------------
Objectif :
Prévoir coûts fixes, marges et modèle d’abonnement.

Éléments :
- VPS-2 ≤30 utilisateurs / VPS-6 >30
- Hébergement : 10€/mois + stockage 5€/mois
- Charges autoentrepreneur : 22% du CA
- Abonnements : free (3 crawls/mois), offre 40€/mois early adopter, 50€/mois ensuite
- Limite autoentrepreneur : 77 700€/an (~129 utilisateurs à 50€/mois)

Estimation bénéfice net annuel :
- 10 utilisateurs : ~4 416 €
- 30 utilisateurs : ~13 776 €
- 50 utilisateurs : ~22 620 €

-----------------------------------------

Semaine 5 : Celery + Redis, intégration Django → Celery → Scrapy, logs
Semaine 6 : interface drag & drop, sélecteurs CSS, stockage S3, liens sécurisés

Semaine 8 : Docker Compose, préparation VPS-2, monitoring minimal
Semaine 9 : déploiement MVP, vérification tâches, CSV, monitoring
Semaine 10 : tests complets, corrections bugs critiques, vérification limites
Semaine 11 : finalisation interface, amélioration UX, support utilisateur
Semaine 12 : tarification early adopter, vérification stabilité, lancement officiel MVP
